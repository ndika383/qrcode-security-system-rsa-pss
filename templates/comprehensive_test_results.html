Mode Validasi Cepat (Accelerated Simulation)

Pengujian ini berjalan lebih cepat karena menggunakan Model Statistik untuk men-generate data pengujian secara instan tanpa menunggu delay waktu nyata (real-time sleep) seperti pada pengujian individual. Ini memungkinkan validasi logika keamanan pada volume data besar (125.000 operasi) dalam waktu singkat.

Pengujian ini menggunakan metode Simulasi Monte Carlo dan Discrete-Event Simulation. Metode ini valid secara ilmiah untuk mengevaluasi perilaku statistik sistem berskala besar (Law of Large Numbers) tanpa kendala waktu fisik.

  • Metode Simulasi: Monte Carlo & Discrete-Event Simulation (Probabilistic Modeling).

  • Distribusi Data: Lognormal Distribution (untuk latensi) & Poisson Distribution (untuk arrival rate).

Analisis Ilmiah & Praktis: {% if scenario == 'normal_operations' %}

Skenario ini mengukur keseimbangan antara kecepatan membuat (Signing) dan memeriksa (Verification) QR Code.

  • RSA 2048: Sangat cepat saat memeriksa (verify), tapi lambat saat membuat (sign). Cocok jika QR Code dibuat sekali tapi discan banyak orang.
  • ECDSA P-256: Seimbang dan gesit. Cepat saat membuat dan cukup cepat saat memeriksa. Pilihan modern untuk sistem yang dinamis.
🏁 Kesimpulan Akhir: Gunakan ECDSA jika sering membuat QR Code baru (dinamis). Gunakan RSA jika QR Code statis (dibuat sekali, scan berkali-kali).
{% elif scenario == 'replay_attack' %}

Skenario ini mensimulasikan pencegahan penggunaan ulang QR Code (seperti tiket bekas).

  • Faktor Database: Kecepatan sistem di sini lebih ditentukan oleh seberapa cepat database mengecek riwayat penggunaan, bukan oleh rumus kuncinya.
  • Observasi: Karena pengecekan database memakan waktu paling lama, perbedaan kecepatan antara RSA dan ECDSA menjadi tidak terlalu terasa.
🏁 Kesimpulan Akhir: Kecepatan deteksi "tiket bekas" lebih bergantung pada database, bukan jenis kuncinya. Keduanya sama baiknya.
{% elif scenario == 'data_tampering' %}

Skenario ini mendeteksi jika isi data dalam QR Code telah diubah secara ilegal.

  • Proses Hashing: Sistem harus membaca dan "meringkas" (Hashing) seluruh data sebelum mengecek tanda tangan.
  • Kesimpulan: Proses "meringkas" ini memakan waktu yang sama untuk kedua algoritma, membuat perbedaan performa total menjadi tipis.
🏁 Kesimpulan Akhir: Keduanya sama-sama tangguh mendeteksi data yang diubah. Tidak ada perbedaan kecepatan yang signifikan.
{% elif scenario == 'signature_forgery' %}

Skenario ini menguji ketahanan sistem terhadap serbuan tanda tangan palsu.

  • Keunggulan RSA: Rumus matematika verifikasi RSA sangat sederhana, sehingga sangat cepat dalam menolak tanda tangan palsu secara massal.
  • Karakteristik ECDSA: Menggunakan kurva eliptik yang rumit, sehingga butuh sedikit lebih banyak waktu komputasi untuk mendeteksi kepalsuan.
🏁 Kesimpulan Akhir: RSA sedikit lebih cepat menolak tanda tangan palsu, tapi ECDSA tetap sangat aman dan memadai untuk standar modern.
{% elif scenario == 'stress_testing' or scenario == 'stress_test' %}

Simulasi saat sistem dibanjiri ribuan permintaan secara bersamaan (High Load).

  • Efisiensi ECDSA: Ukuran kunci dan tanda tangan sangat kecil, sangat menghemat bandwidth jaringan (internet) dan memori.
  • Efisiensi RSA: Karena verifikasinya ringan, beban kerja prosesor (CPU) server lebih rendah saat melayani banyak permintaan scan.
🏁 Kesimpulan Akhir: Pilih ECDSA untuk hemat kuota internet & memori. Pilih RSA untuk meringankan kerja prosesor server saat beban tinggi.
{% endif %}
